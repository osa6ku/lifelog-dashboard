# 検証環境（ステージング）分離と品質チェック手順

本番のスプレッドシート（`ライフログ_日記DB` / `ライフログ_鑑賞記録DB`）および年別Googleドキュメントへのテスト書き込みを禁止し、安全に開発・検証を行うための運用手順です。

## 1. プッシュ前の必須品質チェック（ローカル完結・本番DB非接触）

```bash
npm run check
```

以下を1コマンドで自動実行します：
1. `npm run syntax`: 全フロントJS（`js/*.js`, `sw.js`）および全GASファイル（`gas/*.gs`）の構文チェック
2. `npm run lint`: ESLint による未定義関数・未使用変数・重複キー等の静的解析（ファイル間共有グローバル自動解決）
3. `npm test`: モックAPIを用いた自動回帰テスト（バージョン同期・HTMLイベントハンドラ整合・場所検索/GSIフォールバック・通信タイムアウト＆下書き退避・リッチテキスト変換・タグ集計・GAS純粋関数）

## 2. ステージング（検証用GAS＋コピーシート）の構築・接続方法

本番DBに一切触れずにエンドツーエンドの書き込み検証が必要な場合は、以下の手順で検証環境を分離します。

1. **コピーシート作成**: Google Drive 上で `ライフログ_日記DB` および `ライフログ_鑑賞記録DB` のコピーを作成し、専用の検証フォルダへ配置する（マイドライブ直下には置かない）。
2. **検証用GASプロジェクト作成**: 検証用コピーシートから Apps Script を開き、本リポジトリの `gas/*.gs` を配置（または別 `.clasp.json` で push）。
3. **スクリプトプロパティ設定**: 検証用GASの「プロジェクトの設定 → スクリプトプロパティ」へ以下を登録する（`gas/Config.gs` が自動で読み込みます）。
   - `STAGING_WATCH_SS_ID`: 検証用 `ライフログ_鑑賞記録DB` のスプレッドシートID
   - `STAGING_DIARY_SS_ID`: 検証用 `ライフログ_日記DB` のスプレッドシートID
   - `STAGING_JOURNAL_IMAGES_FOLDER_ID`: 検証用画像フォルダID（任意）
   - `STAGING_JOURNAL_DOCS_FOLDER_ID`: 検証用年別DocフォルダID（任意）
   - `STAGING_YEAR_DOC_IDS_JSON`: `{"2026":"<検証用DocID>"}`（任意）
   ※本番GASにはこれらを設定しないため、本番は従来どおりデフォルトの本番IDで動作します。
4. **フロントエンドから検証用GASへ接続**:
   ブラウザでダッシュボードを開く際、クエリパラメータ `?gasUrl=<検証用GASの/exec URL>` を付与してアクセスします（`https://script.google.com/macros/s/` で始まるURLのみ許可されます）。
